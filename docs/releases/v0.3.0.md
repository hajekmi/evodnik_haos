# v0.3.0

Enabling **Publish state to MQTT** now creates an **eVodnik MQTT** device in
Home Assistant's MQTT integration. It includes an open/close water valve, the
raw and calibrated liter counters, and device/vendor connectivity sensors.
Previously, this option only published JSON topics.

MQTT commands go directly through the local proxy and use the device's verified
status response. Native and vendor commands update MQTT state without command
feedback. Retained command replays, unsupported payloads, offline requests, and extra
MQTT commands while one is pending are discarded. Commands are never replayed
after reconnecting.

Discovery respects HA's discovery prefix and birth/will configuration, refreshes
after reconnect, and uses local config-entry IDs without device serial numbers
or MAC addresses. Disabling MQTT publication or deleting an entry removes its
discovery; unfinished cleanup retries after broker recovery. Changing the data
topic prefix preserves entity IDs and removes obsolete retained state.

Update in HACS and restart Home Assistant Core. Existing MQTT-enabled entries
are discovered automatically. Existing native entities, settings, and meter
calibration remain available. Broker outages do not interrupt native local
control. No additional MQTT credentials or YAML configuration are required.

Validation uses real HA MQTT discovery and synthetic loopback devices, including
open/close actions, vendor state changes, unconfirmed writes, reconnects,
retained commands, command bursts, reconfiguration, and removal during outages.
Physical-device testing remains a user handover step.
